# Ambient 彩蛋

触摸天气壁纸时它会做什么。雷雨天点一下会劈下一道闪电，晴朗的夜晚会划过一颗流星；下雨或下雪时拖动会掀起一阵风，起雾的日子拖动会擦开雾气；而无论什么天气，把首页往下拉，手机就变成一扇望向真实天空的窗。这些都不会预先告知。属于 [Ambient System](./system-ambient.md)；天空本身怎么画，见 [The Sky](./ambient-sky.md)。

## 它们的共同点

| 彩蛋 | 天气 | 手势 | 回应 |
|---|---|---|---|
| [闪电](#闪电雷雨) | 雷雨 | 点击 | 一道分叉的闪电劈到你点的位置 |
| [流星](#流星晴朗的夜晚) | 黑暗、开阔的夜晚 | 点击 | 一颗流星穿过你点的位置 |
| [阵风](#阵风雨和雪) | 雨或雪 | 拖动 | 雨和雪随你的手倾斜，然后平息 |
| [擦雾](#擦雾雾) | 雾 | 拖动（触屏上：先按住，再拖动） | 雾气沿路径散开，然后重新合拢 |
| [天空之窗](#天空之窗任何天气) | 任何天气 | 从顶部把首页往下拉 | 视野随手机转动；太阳和月亮在它们真实的位置 |

每种手势都各不相同，所以同一片天空上，同一只手永远不会同时启用两个彩蛋：点击、拖动、按住（擦雾，或者雨天的[倾斜引导](./ambient-sky.md#the-tilt-primer)，两者不会同时出现），以及会移动页面本身的下拉。

**每个彩蛋都属于 Sky。** 在 Gradient 和 Classic 样式下它们不存在，这是一个决定，而不是遗漏。一层 wash 没有可以画出闪电通道的几何，没有流星可以归属的星空，没有可以吹动的粒子，也没有可以变薄的雾层，所以它最多只能提供一个打了折扣、却装扮成同一样东西的发现。一个彩蛋要有就要完整；做不到的地方，它就不存在。因为缺少 WebGL2 而降级到 Gradient 的 Sky，彩蛋也随之解除。

**"那一下落在天空上了吗？"** 是一个函数，`lib/poke.ts` 中的 `isBackgroundClick`（`isBackgroundPress` 是它的 pointer 事件版本）。它从目标元素一路向上走到 `<body>`，只有路上没有任何东西在绘制（没有背景色或背景图，没有 backdrop filter）、也没有任何可交互的东西时，这次按压才算数。这正是访客已经用眼睛回答过的问题，所以两者不可能有分歧。每个彩蛋都问这个问题，所以小组件卡片、链接、Dock 或打开的 sheet 永远不是天空。如果某个透明图层仍应吞掉这些点击，就给它加上 `data-no-poke`。

**`prefers-reduced-motion` 下没有。** 一个都没有，而且渲染器也会拒绝，所以没有任何东西能绕过这个检查。**什么都不保存**：彩蛋是被发现的，而不是被设置的，重新加载就消失了。

## 闪电（雷雨）

雷雨天点击页面背景，一道分叉的闪电通道在约 70 毫秒内从云底自上而下画出，正好落在点击的位置，经过两次回击闪烁，在 1.2 秒内消失（`POKE_MS.strike`）。它的闪光照亮云层，方式与天气自带的 `lightning()` 相同。

- **用 click，而不是 pointerdown。** 监听器挂在 `wallpaper-background.tsx` 的 document 上，因为壁纸图层是 `pointer-events-none`，而且必须保持如此。click 是在同一位置按下再松开，所以用拇指在天空上滚动永远不会触发它。
- **绝不频闪。** 每个 `POKE_COOLDOWN_MS`（500 毫秒）只响应一次，所以以最快速度点击也只是每秒两次闪光（WCAG 允许三次）。
- **只在天空所在的地方**：天气 kind、整页绘制、以 shader 为引擎。`lib/poke.ts` 中的 `armedPoke` 说明当前场景启用的是哪个彩蛋。
- 入口：`WallpaperRenderer.poke("strike", x, y)`；在 shader 里，`uPokeKind == 1` 驱动 `strike()`。

要看到它：devtool → Sky → 强制 **Thunder**，点击背景。

## 流星（晴朗的夜晚）

在黑暗、开阔的夜晚，点击星空会让一颗流星从屏幕边缘飞入，并**穿过**点击的位置。它和闪电的方式一样（一次点击、一个点、一秒钟），但基调相反：雷雨天以暴烈回应，晴朗的夜晚以一个愿望回应。

**何时。** `meteorPossible()` 问两个独立的问题：

| | 规则 | 归谁管 |
|---|---|---|
| 够暗吗？ | 太阳在地平线下超过 12°（`METEOR_SUN_MAX_DEG`） | 时钟 |
| 有东西挡着吗？ | `scene.clarity` 超过 0.35（只看云量和雾） | 天气 |

−12° 是航海暮光的结束，按惯例流星观测从这里开始。民用暮光（−6°）会让流星出现在一片仍亮得可以看书的天空上；天文暮光（−18°）则会让伦敦在夏天有 59 个夜晚没有这个彩蛋。月亮被有意排除在规则之外：它降低的是你能看到的频率，而不是可能性。`condition === "clear"` 也不在规则里：一个真实的碎云夜晚报告的云量很低，会被启用。（在 devtool 里强制 **Cloudy** 用的是 profile 的 0.7 云量，此时 clarity 为 0；把 Tune → Cloud 拉到 20 % 就能看到多云的夜晚被启用。）

**怎么画**（`shader.ts` 中的 `meteor()`，`uPokeKind == 3`）：

- **它穿过点击位置**，而不是从那里发射：路径从点击点往回推，推到它所遇到的那条边缘外面一点作为入口，再越过点击点继续延伸。流星头在 0.06–0.73 秒（中位数 0.23 秒）时经过点击点，此时亮度绝不低于峰值的三分之一。
- **每次点击重新随机**：方向、倾角（20°–70°，所以永远不会水平或竖直）、弧度、色调和**等级**。一次偏斜的随机（`pow(hash, 1.8)`）决定亮度、彗发、飞行长度、速度、余迹以及是否爆发（`meteorBurst`），所以大多数点击都比较普通，偶尔会有一颗火流星在空中解体。等级就是再点一次的理由。
- **轻微的弧度**，就像大视场会让大圆弯曲：一段圆弧（测量距离很便宜），下落时总是越来越陡，并限制在倾角允许的范围内（`METEOR_PITCH_FLOOR` / `_CEIL`）。
- **恒定速度**（`METEOR_SPEED`）：流星不会减速，它只是不再发光。每次随机一条不对称的亮度曲线（`meteorGlow`），上升之后消耗得比上升时更快。飞行时长限制在 `METEOR_MIN_FLIGHT` / `METEOR_MAX_FLIGHT` 之间；1.7 秒内消失（`POKE_MS.meteor`，shader 的 `METEOR_LIFE` 必须与之一致）。
- **小小的头，短而亮的尾迹，淡淡的余迹。** 眼睛看到的流星是一道短线和一个残影，而不是照片里的完整路径。尾迹（`METEOR_WAKE_TAU`）永远不短于大约两帧的飞行距离，这是根据渲染器测得的帧时间（`uFrameSec`）计算的，所以慢的机器得到的是一道更长的短线，而不是频闪。余迹上的每个点按自己的时钟衰减，比指数衰减更陡（`METEOR_TRAIN_FALL`），所以它永远不会看起来像一根挂在调光器上的硬棍子。
- **颜色取决于空气的"年龄"**（`meteorTint`）：近白色的头，紧随其后的是钠橙色的金属，然后是余迹里的氧绿色谱线。每次随机都会从一次独立于等级的抽取中得到自己的色调。
- **代价由一次判断决定**：它画的一切都落在其圆弧所在的圆上，所以 `abs(length(p - centre) - radius) > METEOR_REACH` 能让几乎每个像素跳过其余计算。
- 画在星星之上、云层之下，所以飘过的云层会遮住残留的尾迹；亮度随 `scene.stars` 缩放。

要看到它：强制 **Clear**，把时钟拖到夜里，点击背景。

## 阵风（雨和雪）

下雨或下雪时，用手在背景上拖过，就会掀起一阵微风；停下或松手，风就渐渐平息。**手为风增加一项**，而天空对风所做的一切它本来就会做（[天气往哪里落](./ambient-sky.md#where-the-weather-falls)），所以没有第二套物理，也没有什么需要归还。

| | |
|---|---|
| 不再移动的手不再产生风 | 它的搅动在一口气之内就失效（`GUST.stirTau`，0.1 秒）；手指停在上面什么也不做 |
| 轻轻一甩扬起一阵微风，长长一扫是一阵大风 | 阵风在 `GUST.attack`（0.13 秒）内升起，所以短促的手势永远达不到满强度 |
| 松手不需要任何宣告 | 搅动不再到来，阵风在 `GUST.release`（1.6 秒）内过去 |

上升和下降相差十倍以上：阵风一下子就来，然后慢慢过去，而速率是按上升还是下降来选的，不是按有没有搅动（来回反向的手会很快把它掀起来）。`GUST.max` 是 1.1，高于预报本身的上限（50 km/h ⇒ 1.0）：一阵风可以短暂地比屏幕上任何天气都猛。对一次 0.5 秒的划动，雨的倾斜随阵风同时达到峰值；雪的倾斜在之后还会继续上升两秒，然后回到原位，没有过冲。这个差距读起来就是重量感。

| 部件 | 职责 |
|-------|-----|
| `lib/wallpaper/stir.ts`（`attachWindStir`） | 识别手势，并以 CSS px/s 报告手的水平速度。 |
| `WallpaperRenderer.stirWind()` | 空气：失效、上升和下降，以及每种东西如何重新对准。 |
| `shader.ts` | 画出它，只通过四个下落 uniform。 |

它不做的事：

- **不调用 `preventDefault`，不碰任何样式。** 每个监听器都是 passive 的；滚动、点击和选择都和没有它时一样。
- **只有水平分量算数。** 竖直滚动不会影响天气。
- **用 touch 事件，而不是 pointer 事件。** 一次变成滚动的触摸拖动会触发 `pointercancel` 并停止发送 `pointermove`，在最好玩的地方把手势切断。
- 在天空干燥时、在选择器的预览图块里、以及在 Gradient / Classic 下**关闭**。

要看到它：强制 **Rain** 或 **Snow**，在背景上拖动。

## 擦雾（雾）

起雾的日子，在壁纸上拖动会沿路径擦开雾气，几秒之内雾又会重新合拢。雾是唯一一种介质真真切切挡在你和景色之间的天气，所以它也是唯一一种天然带着手势的天气。

- **点击**：一个柔和的印记，直径约为视口高度的 5.6 %，没有边缘。**拖动**：擦开的带子跟随路径。**写字**：写一个短短的词，然后手就累了。
- **合拢**：每个点从产生的那一刻起就开始恢复，按一条带长尾的指数曲线（`WIPE_DECAY`），在 `WIPE_LIFE_MS`（8 秒）内消失。不会停留：雾从不让你看一个完成的印记。

**一条路径，而不是一个点。** fragment shader 没有记忆，所以 `WallpaperRenderer.wipe(x, y)` 维护一个有界的环形缓冲，存放路径最近的**拐点**，`fogWipe()` 沿折线扫出擦开的带子。没有 FBO，没有第二个 pass，没有纹理。

- 每个合并的 pointer 采样都按顺序放进去，所以快速划出的曲线不会变成帧与帧之间的弦。
- 拐点按**形状**提交：当自上一个拐点以来走过的距离与直线距离相差 `WIPE_SLACK` 时。一段直线每隔 `WIPE_MAX_GAP` 才用一个；一个字母则按它的弯曲需要多少就用多少。
- 笔画彼此独立（每个拐点都标明它是否延续上一个），移动距离超过 `WIPE_JUMP` 就开始新的一笔。
- 当前拐点的包围盒以 `uWipeBox` 传给 shader；盒子之外的像素只需一次包围盒判断。

**它揭开的是什么。** 擦雾的意义在于上面有一片真实的天空。但在雾天，场景已经把它藏起来了：0.75 的云量让星星归零，0.9 的雾让月亮只剩 0.07。所以场景还会交出 `scene.behind`（前面既没有雾、也没有雾层时的星星和月亮），shader 按一个片元失去了多少浑浊度向它插值。以 `uFog` 为门控，有三样东西一起让开：雾、云层（雾天里云层*就是*浑浊本身），以及夜空（`uStarsBehind`、`uMoonBehind`），以晴朗天空会给它的亮度显示。清澈的空气散射更少，所以擦开的带子比雾气略暗一点。

**没有圆，没有边缘。** 雾里的一个圆看起来像一片镜片：这个场通过雾自身噪声的 domain warp 来查找，宽度再被另外两个尺度推来推去，留下一缕缕没擦掉的雾。衰减是高斯的，在任何宽度下都没有肩部，因此没有轮廓；带轮廓的笔画是最像笔的东西。擦开的带子随时间顺风漂移并沉降，像下落一样按重力解算（`aimWipe`），所以倾斜手机也会让漂移倾斜。

**手会累**（`lib/wipe.ts`）。真的去擦一扇起雾的窗户，手指很快就擦不出什么了；歇一会儿又能擦了。这就是一张会回应你的壁纸与一块画板之间的区别。

- 按擦过的距离消耗（`WIPE_DRAIN`），直到一个下限（`WIPE_SPENT`），所以累了的手仍然能抹开一点。横扫一下大约剩下四分之一；这个预算就是要在第一笔之内就让人感觉到。
- 按离开玻璃的时间恢复（`WIPE_RECOVER`，在间隔超过 `WIPE_REST_S` 之后）。字母之间抬手不会补充它；等待才会。
- 每个拐点保存手当时的电量，所以衰减是*沿着*路径分布的。它编码在 `uWipe[i].w` 的符号和大小里。

**它不和页面打架。** 用鼠标时，它会等到移动超出容差，所以在天空上的单击、双击和选词都和以前一样。一旦确定是擦雾，这一笔期间文本选择会被抑制。它从不在小组件上开始（dnd-kit 的排序不受影响），并在首页网格的编辑模式下退让，那时点击背景意味着"完成"。

### 触屏上，滚动优先

手指放在天空上可能是要滚动，而这无法通过观察它往哪个方向走来判断：只有非 passive 的 `touchmove` 能阻止滚动，而且只能在滚动开始之前，在 iOS 上那就是手指还没移动的时候。所以**长按来启用它**，用的是和小组件网格相同的 400 毫秒（`TOUCH_HOLD_MS`、`TOUCH_ACTIVATION`）。

- 在按住生效之前什么都不绑定；页面在浏览器的快速路径上滚动。非 passive 的监听器在一笔启用时挂上，结束时移除。
- 如果先漂移超过 `WIPE_ARM_SLOP_PX`，那就是滚动的；什么都没拿走。
- 启用时手指下方的雾会散开：这是唯一的"准备好了"的提示，而它就是效果本身。
- **写字是一个个字母**：一笔结束后的 `WIPE_RESUME_MS`（1.2 秒）内，落在离结束位置 `WIPE_RESUME_NEAR` 以内的触摸会立即启用。
- 第二根手指意味着捏合或一次新的滚动；手势会被交还。

在触摸模拟下验证过：普通的划动滚动 245 px，什么也不画；先按住再竖直往下拖，滚动 0 px 并画出痕迹；在恢复窗口内的下一笔不需要按住就能画。

要看到它：强制 **Fog**，在背景上拖动（手机上要先按住）。

## 天空之窗（任何天气）

把首页往下拉，舞台就变成一扇**窗**：指南针告诉你面朝哪个方向，俯仰告诉你抬头看多高，横滚告诉你哪边是水平。太阳和月亮在星历给出的位置：转过身，它们就在你身后；把手机朝下倾，就有一条地平线，下面是地面。往上划，它又变回壁纸。`lib/sky-window.ts`。

它是对陀螺仪的另一种理解，正是[倾斜](./ambient-sky.md#gyroscope-tilt)有意不采用的那一种：那里舞台仍然是一幅构图，里面有一个重力；这里是视野在转动，所以渐变、天体、星星、云和雾都随之转动。

### 坐标系和指南针

世界是东-北-上坐标系，方位角从北顺时针计算，与 `lib/solar.ts` 给出的一致。一个视角是三个单位向量：屏幕的右方、上方，以及它看向的方向（从手机背面朝外），由 W3C 角度 `R = Rz(α)·Rx(β)·Ry(γ)` 再按 `screen.orientation.angle` 旋转得出。从视角读出的重力与 `gravityFromOrientation` 一致，所以窗口的地平线和雨的下落方向永远不会有分歧。

| 浏览器 | 北从哪里来 |
|---|---|
| Chrome / Android | `deviceorientationabsolute`；它在持续发送时，相对事件被忽略 |
| Firefox | 带 `absolute: true` 的 `deviceorientation` |
| Safari / iOS | alpha 相对于开始监听时的方向；`webkitCompassHeading` 随附在旁边，只在手机顶边足够水平、可以指向任意方向时才估算偏移 |
| 没有指南针 | 第一次读数锚定到舞台自己的朝向（南；南半球为北）；devtool 用 `~` 标记这个朝向 |

**真北，而不是磁北。** 每个浏览器的指南针都是磁北，而磁偏角常常超过 10°（旧金山 +13°，纽约 −12.5°）。所以每个朝向都按观察者所在地点和时间的磁偏角旋转，磁偏角来自世界地磁模型（`lib/magnetic.ts`：WMM2025 系数，适用于 2025–2030，超出范围时取最近的端点），作为 `celestial.declination` 随场景传递，没有坐标时为 0。它已经对照模型公布的 100 个测试值做过校验。没有哪个全球模型能消除一张钢制桌子或手机壳里的磁铁。

### 透过玻璃

渲染器负责几何，shader 负责像素。`uWindow` 在 `WINDOW_TAU` 内从 0 缓动到 1，每一行读取窗口 uniform 的代码都放在对它的判断之后，所以在 0 时舞台与没有天空之窗的构建逐位相同。

- **天空按高度角着色**：每个像素是一条射线，渐变读取 `HORIZON_Y + 0.9·sin(elevation)`，也就是舞台用来放置太阳的映射。
- **天体是投影出来的**：针孔模型，沿屏幕较长边 `WINDOW_FOV_DEG`（80°）。在你身后的天体被停放在它所在方向的屏幕外，所以当它转过去时，它的光晕会渐渐消失。
- **它们飞过去**：先停在舞台原来放它们的位置，然后在 `BODY_FLY_DELAY`（0.25 秒）之后，用 `BODY_FLY_SEC`（1.2 秒）沿一条轻微的弧线飞到它们真实的位置。在你身后的月亮从你应该转向的那一侧边缘飞出去。
- **边缘提示**（`<SkyBodyHints />`，图标来自 `components/body-glyph.tsx`）：在地平线上方但不在玻璃里的天体，会在屏幕边缘、朝向它的那条线上，以 60 % 显示其实心图标和一个箭头。太阳有光芒，月亮永远没有。在日出或日落窗口期间，太阳的提示是一个指向其光源的 `SunEventGlyph`（`WindowBodies` 上的 `sun.light`）：升起时指向太阳，落下后指向它下方的地平线。渲染器每帧发布天体位置（`lib/sky-bodies.ts`）；提示自己移动自己的元素，不需要每帧做一次 React 渲染。
- **月牙朝向太阳**，沿两者之间的大圆，无论横滚角是多少。
- **云层是头顶上的平面**，向地平线汇聚，在靠近地平线处让位于它们的平均效果，真实的阴天在那里正是这样。
- **星星位于一个随恒星时钟转动的球面上**（`celestial`：纬度和当地恒星时），每颗至少一个像素宽，这样视角移动时不会突然闪现。
- **地平线以下是地面**：地平线的颜色，越靠近你的脚越暗。
- **雨按横穿你视线的风倾斜**（`windWorld`），并且无论倾斜开关怎么设置，都沿真实的重力落下，因为一扇窗里有一个世界。

仍然在屏幕空间里的：雨场和雪场本身、闪电、闪电彩蛋、流星和擦雾，它们是玻璃前面的东西。

**只在当前会话有效**，离开首页时暂停（缓动回舞台）。减少动态效果下关闭；选择器的 Sky 图块永远不跟随它。

### 下拉

首页的构图偏下，上面是天空。**从顶部往下拉，它就下沉：视线随之抬起。** 越过一条线后松手，天空之窗打开，首页继续从画面底部离开。**往上划**（`RETURN_SWIPE_PX`）把它带回来。`lib/sky-pull.ts`。

为什么是下拉：页面往下就是视线往上；每个人都习惯性地把页面顶部往下拉，所以它会以彩蛋应有的方式被发现；它和那些把手放在壁纸上的彩蛋毫无共同之处；而且检测它不需要任何权限。

**上面有东西。** 没有回应的下拉会停在半路，所以页面往下来的时候，位于地平线上方的那个天体会从顶边上方降下来（`<SkyPullCue />`），画成**光**（一个带泛光的白色天体），下面是 "keep pulling to look up"，到达那条线时变成 "let go to look up"，在支持 `navigator.vibrate` 的地方还会震动一下。日出或日落期间，它是该事件的图标。天空的渐变在它下面抬升（`uLift`，最多 0.16 个屏幕）；天体、云和星星在天空之窗打开前保持不动。

**每帧不经过 React。** 识别器在跟随手指的元素上写三个 CSS 变量（`[data-sky-exits]`：首页内容和搜索按钮；以及 `.sky-pull-cue`），而不是写在 `<html>` 上，所以一次移动只重绘这些元素，而不是通过继承重新计算整个文档的样式。它在 `<html>` 上设置 pulling / armed / returning 属性，并调用 `WallpaperRenderer.previewWindow()`；天空之窗打开后，`wallpaper-background.tsx` 设置 `data-sky-window`。移动由 CSS（`app/globals.css` 中的 "The sky pull"）完成。

| 变量 | 含义 |
|---|---|
| `--sky-pull` | 页面跟随了多远（带橡皮筋阻力） |
| `--sky-pull-progress` | 距离那条线还有多远 |
| `--sky-pull-reveal` | 提示显示了多少：前 `REVEAL_FROM_PX`（46 px 页面距离，约 8 mm 手指距离）什么都不显示，之后一路 smoothstep 到那条线 |

| 属性 | 首页 |
|---|---|
| `[data-sky-pulling]` | 跟随手指，稍微变淡 |
| `[data-sky-armed]` | 超过 `PULL_ARM_PX`（104 px），只有低于 `PULL_DISARM_PX`（96）才解除，这样颤抖的手指不会让说明文字闪烁 |
| `[data-sky-window]` | 加速从底部离开，并且不再可触摸 |
| `[data-sky-returning]` | 短距离下拉之后或天空之窗关闭时缓动回来 |

静止时完全没有 transform，因为 `<main>` 上的 transform 会让它成为其内部所有 fixed 元素的包含块。

**它在第一次移动时就认领这次触摸**，因为已经开始滚动的浏览器不允许取消 `touchmove`，而取消是阻止 iOS 橡皮筋效果和 Chrome 下拉刷新的唯一方法。所以认领的条件很窄：在页面顶部，向下移动多于横向移动，在 `.system-surface` 上（首页；见 [Four voices](./design-system.md#four-voices-chrome-surface-voice-document)），在落下后的 `CLAIM_BEFORE_MS`（320 毫秒）之内，按事件的时间戳计算，因为先停住的手指是要拿起一个小组件。在天空之窗里，天空上的每次移动都会被取消；sheet 或 Dock 保留它们自己的触摸，点击仍然能触发闪电和流星。

### 请求天空之窗

在 WebKit 上，运动数据挡在 `DeviceOrientationEvent.requestPermission()` 之后，所以只要这道门还在，**下拉就会弹出天空之窗的说明，带一个发起请求的按钮**（`SkyWindowSheet`）。门已经过了，或者根本没有门，下拉就直接打开天空之窗。只要门还在，每次都会邀请：越过那条线的下拉已经足够刻意，回应它不算骚扰。同意也会打开倾斜的意愿，所以雨天就没有别的可邀请了。

- **画面**是一部手机在一片淡淡的天空上平移，同一片天空在手机里完整地画出来，手机移动时它保持不动；太阳进入窗口又离开。用 CSS 实现，嵌套结构让内部世界抵消手机的移动；减少动态效果下停在 0%。
- **结果**：已授权（1.4 秒，"hold the phone up and turn around"，后面的天空之窗已经在打开）、被拒绝（3.0 秒，停在太阳和月亮之间，并说明去哪里撤销），两者都不是（按钮会回来）。之前被拒绝过的话，下拉会直接打开拒绝页面。
- **位置也在同一口气里。** 一扇对准真北、却开在错误城市上空的窗是失败的，而 IP 猜测常常差一座城市。所以当正在使用的位置只是这个猜测时（`locationStatus` 是 `askable`），sheet 会说它也会请求位置，一次点击通过 `usePermissions` 同时请求两者（[权限](./system-ambient.md#permissions)）。位置邀请每个会话只出现一次（`skyLocationOffered`）；下拉和 sheet 用同一个函数 `skyAsksPlace` 决定是否请求，所以 sheet 永远不会说出下拉本没有打算的事。

**Devtool。** Sky → Window 可以切换它（桌面上也可以），并显示朝向 · 俯仰；开启时，Heading 和 Pitch 滑块可以手动驱动视角，直到这一行的星号把它交还给传感器。**Motion** 折叠区显示传感器报告的内容：北从哪里来（`absolute`、`flagged`、`webkit`、`anchored`、`simulated`）、事件频率、原始 α β γ、屏幕角度、WebKit 的指南针朝向和精度、应用的偏移和磁偏角、视角的朝向、俯仰和横滚，以及当前存在哪些稳定原因。
