# Reactive Intents：模型驱动一切，其余都是捷径

> reintent（来自 airtalk#818，`packages/reintent`）不只是"按屏幕自适应"的工具。把它当成一种 **Reactive Intents-Oriented Programming**：意图树是唯一的 state，任何事件（拖拽、resize、一句 prompt、一次编辑）都交给一个回调，结果走同一个 reducer，再单向地算出每个上下文里的样子。
>
> **模型驱动一切。** 意图树（有哪些意图、每个意图的选项、每个选项改哪些旋钮、什么话和什么手势表示哪个选项）是强模型写的数据。人的 resolve、代码的计算和 effect、弱模型的 infer，都只是走它写下的东西的 **short path**：更快、更便宜，但不比它多知道什么。
>
> 原型：`/lab/intent`（`app/lab/intent/`），对象是 `/dream/forget`。这份文档是 brainstorm 和原型的结论。

## 一张图

```
                    强模型 author ──▶ 意图树（意图 · 选项 · 补丁 · 词汇表）= 数据
                         │ 重新编写                   ▲ add（新意图 + 这次事件的词汇）
                         ▼                            │
  ┌──── state：意图树 + 人的决定 + 模型的信念 ────┐   │
  │                                               │   │
  ▼                                               │   │
  reintent（code）── 每个上下文一份 Assignment ── compile ──▶ props ──▶ 视图
                                                  │                         │ 事件：拖拽 / prompt / 切换 / 回答
                                                  │                         ▼
                                                  │   ① 词汇表匹配（人的 resolve，零模型，~1 ms）── 命中 ──▶ decide
                                                  │         │ 没命中
                                                  │         ▼
                                                  │   ② 弱模型 select（只读文字）：有把握时 ──▶ believe（模型的判断，不学）
                                                  │         │ 没把握 / 没有合适的选项 / 是一个拖动
                                                  │         ▼
                                                  │   ③ 强模型：代人 decide ── learn ──▶ ①；或 believe；或 add ──┘
                                                  │
                                                  └──────────── reduce(state, action) ◀── 每个回答都先过 admit
```

| 路 | 谁 | 做什么 | 代价 | 原型里 |
| --- | --- | --- | --- | --- |
| author | 强模型 | 从场景写出整棵意图树，连同词汇表；重新编写时人的决定、学到的词汇、为事件新加的意图都保留 | 一次，后台 | `ask("author")`、`acceptAuthoring`；缓存在 `forget.ts`（`PRESET`） |
| ① | 人（零模型）| 事件在词汇表里：一句话、一个手势正好表示某个选项 | ~1 ms | `recognize`：通用匹配器，没有一行手写手势 |
| code | 代码 | reintent 的优先级、交叉、compile、校验 | 微秒 | `typesOf`、`compile`、`admit` |
| ② | 弱模型 | **只读文字，只能选，只形成判断**：有把握（≥ 0.7）时，它的理解是一个 belief（模型的，排在人的任何决定之下，不学进词汇表）；拖动不走这里 | 一次便宜的调用（1–2 s）| `ask("select")`、`acceptSelection`、`weakReads` |
| ③ | 强模型 | 弱模型没把握、没有合适的选项、或是一个拖动：**代人决定**（并学进词汇表，下次就是 ①），或形成判断，或新加一个意图（词汇里带上这次事件） | 一次贵的调用 | `ask("add")`、`acceptAddition`、`lessonOf` |

| 这里 | 对应 | 原型里 |
| --- | --- | --- |
| state | Redux store / React state | `tree`（意图树，数据）、`store`（人的决定、偏好）、`beliefs`（模型的分布，缓存）|
| action | Flux action | `decide` / `forget` / `believe` / `add` / `replace` / `learn`（`model.ts` 的 `Action`）|
| reducer | reducer | `lab.dispatch(action)` |
| selector / computed | `useMemo` / signals | `view(key, screen)`、`params(screen)`：reintent 的 computed，值不变就不往下传 |
| event callback | `onClick` | `handle(event)`：同一个回调接住拖拽、prompt、切换、回答 |
| effect | `useEffect` / thunk / ReAct 的 act | `ask(mode, observation)`：模型观察（树、决定、事件、上下文）并写出一个 action |
| context | Context / 媒体查询 | 屏幕（`tallness` 是交叉的索引），以及之前的 prompts |
| view | 组件 | 真正的 `/dream/forget` 场景，按每块屏幕的尺寸装进盒子里跑 |

## 交互：意图看得见

意图是数据，所以界面可以在人动手**之前**就把它们摆出来：

- **意图落点（drop zones）。** 按下的那一刻，从词汇表里找出所有"从这里出发"的手势，排除已经不可能的（从窗外开始的"拖出窗"），把每一个画成落点并写上名字：拖出窗外是"留住你的猫"，横着拖是"横向"。拖动中实时算出松手会是哪一个，点亮它，并在每块屏幕上预览它的结果；哪个都不是时，提示"松手：交给模型"。落点完全由词汇表推出来，强模型重写了树，落点也跟着变，界面不需要改一行。
- **模型已经想到的方向。** 每个意图没被选中的选项（reintent 的 alternatives：一次只换一个，其余冻结），按模型的判断排序，标出这是模型的判断还是代码的先验。鼠标移上去，焦点屏和墙上每块屏幕都预览过去，会变的屏幕标出"会变"；点击就是你的。手指没有 hover：第一下预览，第二下确认。预览是 `lab.whatIf(action)`：把状态 fork 一份、在 fork 上 dispatch，什么都不提交。
- **画布上的 magic move。** 梦画在 canvas 上，CSS transition 管不到。所以在舞台内部做：窗的形状一变（换方向、窗里放几张、屏幕尺寸变了），画出来的窗和其中的画面都从原来的位置移到新位置（`kinds/morph.ts`，0.6 秒，先慢后快再慢），留住的画面也跟着走。切换、预览、拖动松手、调整窗口大小，都是连续的。

这三样合起来是一种新的编辑方式：**不是在属性面板里找一个值，而是看着模型准备好的几个方向，指一下就看到结果，点一下就定下来。**

## 在别的梦里

落点和方向不是 forget 的功能，是意图树的功能。实验室现在能切换三个梦（`?dream=everyone`、`?dream=blue`），页面上的代码不知道当前是哪一个：落点从词汇表推，方向从信念推，预览从 `whatIf` 推。每个梦只需要一棵树（`everyone.ts`、`blue.ts`，和 forget 一样是强模型编写结果的缓存）和几行展示用的东西（`dreams.ts`：场景、底色、它的东西怎么称呼、点击时谁先）。

换了梦，同样的交互说的是不同的事：

| | forget（记忆） | everyone（叙事） | blue（构图） |
| --- | --- | --- | --- |
| 意图是什么 | 留下还是放走、往哪走 | 世界怎么转、多少人在说话、安静怎么散开、那一点光怎么走近 | 太阳在哪、地平线在哪、太阳多大、海怎么打开、听不听得见 |
| 手势的意思 | **拥有**：拖出窗 = 留住，拖回 = 放手 | **对世界做一个动作**：横推 = 转快，下按 = 停住，往外拉 = 变大 | **直接摆**：太阳往左拖 = 偏左，海往上拖 = 海多 |
| 落点长什么样 | 形状（窗、窗外） | 动词（从按下处伸出的箭头） | 方向（箭头），落点就是几个构图 |
| 预览是什么 | 布局 magic move（窗和画面滑过去） | 数值滑过去（世界变大）；**节奏要重演** | 数值滑过去（太阳挪过去、地平线升降） |

两个新东西是在别的梦里才长出来的：

- **数值也要 magic move。** forget 的变化是离散的（换方向、几张一行），在 kind 里自己做动画。everyone 和 blue 的意图大多是一个数（球的大小、太阳的 x），所以宿主加了一层：`morph` 打开时，覆盖在场景上的数值从旧值缓动到新值（`store.ts` 的 `set` / `resolve`，0.6 秒），每个 kind 都不用改。
- **关于"一个时刻"的意图，预览要把那个时刻重演一遍。** "安静是一下子到达所有人，还是一圈圈传出去"，静止时看不出来：它只在你碰到一个声音的那一刻存在。所以这类意图（`Dream.replay.keys`）被 hover 时，焦点屏和会变的屏幕从头再演一次，并且马上就碰（everyone 0.6 秒碰一下，blue 0.4 秒按住）。在两个方向之间移动鼠标，就是在同一个瞬间的两种演法之间来回切换。

还有一个小的：动手改时，梦停在开头等你（不再自己演），否则你要拖的东西（球、太阳）可能在你按下之前就退场了。

**再往外想：别的类型的梦里，这套交互能做什么。** 每一条都是"意图是闭集的选择 + 手势是词汇 + 预览是 whatIf"，只是落点和预览的形态不同：

- **声音的梦。** 意图是配器和情绪（弦乐/钢琴、近/远）。把一个声部拖出"前景"的框 = 退到背景；hover 一个方向 = 用同一段的四小节交叉淡入试听。预览是时间性的，和 everyone 的重演一样，只是重演的是声音。
- **分支叙事的梦。** 意图是下一幕的走向（和好、离开、沉默）。方向就是模型准备好的几个结局；hover = 快进出那一幕的幽灵版本（半透明叠在当前画面上），点击才真的走过去。把一个角色拖到另一个角色身上 = 他们之间关系的意图，落点是对方的形状。
- **地图 / 旅程的梦。** 意图是路线上每个地方停不停、停多久。把一个地点拖出路线 = 跳过，拖回 = 停留；方向是"更慢的一天""只走海边"这样的整体路线，hover 时路线线条 magic move 到新的走法。
- **肖像 / 光的梦。** 意图是光位（顺光、侧光、逆光、伦勃朗光）。手势是绕着脸转一圈（新的方向词：`around`），落点是几个光位的弧；hover 立刻重新打光。和 blue 一样是构图，但落点是一条弧而不是一个方向。
- **花园 / 生长的梦。** 意图是季节和生长的速度。往上拖一株植物 = 长快；方向的预览把时间快进一段再倒回来：预览不是一帧，是一段被压缩的时间。
- **一封信的梦（文字）。** 选中一句，方向是改写的几种语气（更克制、更直白、更温柔）；hover 时字词级的 diff 做 magic move（相同的词不动，换掉的词滑进滑出）。落点：把一句拖到信的末尾 = "把这句留到最后说"。
- **多人的梦（everyone 的延伸）。** 别人的决定是一层偏好：落点旁边标出"有 3 个人在这里选了停住"，方向按别人的选择排序，而你的决定仍然压过所有人的。

从这些里能抽出几种新的交互形态，原型里只做了前两种：

1. **吸附到意图（snap to intents）**：连续的拖动，松手时吸附到模型准备好的离散选项上（blue 的太阳）。像智能参考线，但参考线是意图，不是像素。
2. **重演预览（replay preview）**：时间性的意图，hover 时把那个时刻重演一次（everyone 的安静、blue 的海）。
3. **幽灵预览（ghost preview）**：分支和结局，叠一层半透明的"如果"，而不是替换当前画面。
4. **群体落点**：落点上显示别人的选择，作为偏好而不是决定。

## 三条规则，原型里才想清楚的

1. **模型写的是数据，不是代码。** 模型的产出只能是那几种 action 之一；新意图是一个节点：闭集的 kinds，每个 kind 是一组 props 补丁。`admit` 拿舞台上实际有的旋钮（值、单位、范围）校验：不存在的实体、不存在的旋钮、越界的数、只有一个 kind、`resolve` 写错，都放不进来（`intent-lab.test.mjs` 里有一条把这五种错一次列全）。
2. **人的决定永远压过模型。** 一句"更伤感"不是一个选择，是一种情绪：它变成 `believe`，改的是模型对好几个意图的分布；人已经决定过的那个（尘"升起"）原样不动，模型因此变得够确定的那个（"按住时"0.8）从此不再问。这就是 reintent 的优先级（人 > 偏好 > 足够确定的模型 > 代码）在"reprompt"上的含义。
3. **每个新意图的第一个 kind 是"原样"，而且每个 kind 都写同一组旋钮。** 缺的由 `admit` 用场景写的值补齐。所以切回去永远等于撤销，模型加的意图和预设的意图一样可以切换、可以忘掉。

还有一条反过来的：**② 可以回答 "none"，而且应该说缺什么。** 把一个画面拖到另一个画面上（重排），没有任何旋钮能表达顺序，模型（和替身）都回答 none，并指出"这需要重新生成 kind，而不是做一个选择"。这正好划出了第三层：意图树之外，是改代码（重生成一个 kind）。

## User cases

图例：**①** 词汇表就能 resolve，不调模型；**②** 要模型（弱模型选，或强模型加）；**✓** 原型里已经做了。"存什么"一栏只列会被持久化的东西（人的决定、模型写的意图），其他都是算出来的。

### A. 直接操作：手势就是事件

| # | 用户做了什么 | 事件 → 意图 | 路 | 存什么 |
| --- | --- | --- | --- | --- |
| A1 ✓ | 把一个画面拖出窗外 | drag(moment#i → 窗外) → `keep|moments#i = stays` | ① | 一条决定 |
| A2 ✓ | 把留住的画面拖回窗里 | drag(aside → 窗内) → `keep = goes`：它在原地化成尘 | ① | 一条决定 |
| A3 ✓ | 把窗横着拖 / 竖着拖 | drag(window, 水平) → `axis = across`，**在这块屏幕的形状上**挪交叉点 | ① | `{base, below, at}` |
| A4 ✓ | 把尘往下拉 | drag(dust, ↓) → `dust = settles` | ① | 一条决定 |
| A5 ✓ | 把一个画面拖到另一个画面上（想重排） | 没有预设，没有旋钮 → 模型回答 none，指出要重生成 kind | ② | 无 |
| A6 | 双指捏窗口 | pinch(window) → 一个新意图"窗多宽"，或已有的 `held`（窗里放几张） | ①/② | |
| A7 | 长按一个实体 | 列出它所有意图的 alternatives（reintent 的 `alternatives`：只翻一个，其余冻结）作为一键切换 | ① | 无 |
| A8 | 在空白处画一个圈 | 不认识的手势：模型把轨迹和树一起看，可能推断成"把尘聚到这里"（新意图 + 坐标作为补丁） | ② | 模型写的意图 |
| A9 | 编辑器里把元素拖到角落停靠（演说原型的"dock 到哪"） | drag → `anchor = pin` 或 `flow`；落点就是 kind | ① | 一条决定 |

### B. Reprompt 一个实体：选中它，说一句

| # | 说了什么 | 发生什么 | 路 |
| --- | --- | --- | --- |
| B1 ✓ | 选尘，说"落下" / "settles" | 正好是一个 kind 的名字：识别器直接 resolve，不调模型 | ① |
| B2 ✓ | 选画面，说"慢一些" | 没有意图管节奏 → 模型 `add` 一个 `pace|moments`（原样 / 慢一些，补丁是 `gap`），并决定"慢一些" | ② |
| B3 ✓ | 说"像雪一样落下" | 不是 kind 的名字，但等于一个已有的 kind → 模型 `decide dust=settles` | ② |
| B4 ✓ | 对整个梦说"更伤感" | 情绪 → `believe`：好几个意图的分布一起动，人的决定不动 | ② |
| B5 | 选一个画面，说"换成我外婆" | 内容的 reprompt：意图是"这个画面是谁"（闭集外），模型重画 sprite。这是 reintent 的 **lazy effect**：写出来的画按它写时的意图（`under`）缓存，意图变了就藏起来、改回来就回来 | ② + 缓存 |
| B6 | "这句结尾太直白了" | 结尾的字是一个 `words` 意图：原样 / 模型改写的几版；模型写的每一版记下 `under`；切回原样就是撤销 | ② |
| B7 | 对窗说"别那么规整" | 没有旋钮能表达 → none，并给出它需要的 kind 改动（例如 `jitter` 参数），交给第三层 | ② |
| B8 | 同一个 prompt 说两次 | 第二次命中 ② 的缓存（按树的哈希 + 事件签名）：**被模型推断过的映射可以升格成预设**，像 JIT 一样从 ② 变成 ① | ①（缓存后）|

### C. 用户编辑：手改的东西也是意图

| # | 编辑 | 建模 | 路 |
| --- | --- | --- | --- |
| C1 | 改结尾的那两句字 | 一个 `words` 意图多了一个 kind"你的"，并决定它；原文作为另一个 kind 留着，一键切回 | ① |
| C2 | 在检查器里把滑杆拖到某个预设 kind 的值附近 | 吸附：识别成那个 kind（`decide`），而不是一个裸数 | ① |
| C3 | 把滑杆拖到任何 kind 都不像的地方 | 新的"自定义"kind（数据），或者交给模型找一个名字和它的对立面 | ①/② |
| C4 | 改了中文版的字 | 英文版是模型写的、`under` 中文那一版的 lazy effect；中文一改它就过期，后台重写，写好之前显示旧的 | ② + 缓存 |
| C5 | 撤销 | 不是"反向操作"，是恢复 state 快照（树 + 决定 + 信念）；模型写的意图也一起回去 | ① |
| C6 | 两个人同时改 | 决定按 key 合并；同一个 key 冲突时保留两个人的，作为 alternatives 让人选 | ① |

### D. 上下文不只是屏幕

| # | 上下文 | 意图 | 怎么变 |
| --- | --- | --- | --- |
| D1 ✓ | 屏幕形状 | `axis`：按 `tallness` 交叉 | 拖窗或切换，交叉点挪到这块屏幕 |
| D2 | 用户说"我只有几秒钟" | `pace` 按"可用时间"索引：短于某个值就快 | prompt 先变成上下文，不是决定；之后所有按时间索引的意图都跟着 |
| D3 | 系统的"减少动态效果" | `motion`：完整 / 安静，按偏好 | 一个偏好，所有场景都用 |
| D4 | 夜里 | `glow`：按一天中的时间交叉（暗一点） | 不用人做任何事，代码按上下文算 |
| D5 | 观众（一个人 / 投到大屏上） | `scale`、`words` 的长短 | 编辑器里预览两种上下文 |
| D6 | 之前说过的话 | 模型 infer 时看到最近几句 prompt（原型已经传了） | "再慢一点"能接着上一句 |

> **resize 是上下文事件，不是意图事件。** 窗口变了，state 不变，只是同一份意图在新的上下文里重新算一次。只有当用户**在某个上下文里做了决定**（在横屏上把窗竖起来），才产生 action，而且这个 action 带着上下文（交叉点挪到这里）。

### E. 偏好：一次说清，到处适用

| # | 说了什么 | 建模 |
| --- | --- | --- |

## 原型里做了什么

- `tree.ts`：意图树是纯数据（`IntentNode`：`type`、`of`、`kinds` 各带补丁、`prior`、`resolve`、`index`，以及词汇表 `say` / `gestures`）。`typesOf` 把树变成 reintent 的类型；`compile` 合并补丁（列表取并集：所有留住的画面）；`admit` / `admitTree` 校验并补齐模型写的节点和整棵树；`learn` 往词汇表里加一句话或一个手势。
- `forget.ts`：**强模型编写的结果的缓存**（`PRESET`，标明 `by`），这样不调模型也能打开；它和模型写的树过同一套校验，测试里有一条拿真正的 kind 声明和场景写的值去校验它。
- `model.ts`：state 和唯一的 `dispatch`。`replace`（重新编写）保留仍有意义的人的决定、学到的词汇、为事件新加的意图。
- `events.ts`：
  - `recognize`（①）：通用匹配器，拿事件去对词汇表。手势是数据：从哪里开始（`self` 或某个实体）、往哪个方向、离开或进入哪个实体的形状。
  - `acceptSelection`（②）：弱模型只能 decide / believe / none；`none` 带 `escalate` 表示"旋钮能表达，但没有合适的选项"。
  - `acceptAddition`（③）：强模型加的意图，词汇里自动带上这次事件。
  - `acceptAuthoring`：强模型写的整棵树。
  - `ask(mode, …)`：调 `/api/intent`；没有模型时用标明是替身的规则集；模型答坏了算失败，不会悄悄换成替身。
- `app/api/intent/route.ts`：三种模式，两个模型。`select` 用弱模型，`add` / `author` 用强模型；`INTENT_WEAK_MODEL` / `INTENT_STRONG_MODEL` 可以换（默认 gateway 免费层的 Qwen 3.5 Flash / Gemini 2.5 Flash）。
- `/dream/forget` 的画面可以被留住（`kept`）；窗沿是否磨损是一个真正的旋钮（`edge.wears`），不再是一个魔法数。
- 验证：`scripts/tests/intent-lab.test.mjs` 16 条（其中一条拿真实的 kind 声明和场景写的值校验缓存树，它找出过 `window.axis` 没有声明、`tide.stagger` 的范围太窄）；浏览器里 ① 拖窗（3 ms）、② 弱模型把"像雪一样慢慢落下"读成判断（不学，第二次仍走 ②）、③ "let them linger" 升级到强模型新增节奏意图（学会，再说一次 0.8 ms 走 ①）、重新编写（为事件加的意图和它的决定保留下来）。

## 真模型上（Vercel 预览，gateway 免费层：弱 = Qwen 3.5 Flash，强 = Gemini 2.5 Flash）

**第一轮，只有一个模型、什么都让它做**（同样五个事件，三次）：结构错（键写错、把类型名当 kind）被 `accept` 拦住；意思错（`holdRate` 调大当成"停留更久"、把拖动当成"留住"）拦不住；同一个事件每次答得不一样。

**改成"强模型驱动，其余是捷径"之后**，一步步在真模型上暴露、修掉的：

| 发现 | 改了什么 |
| --- | --- |
| 强模型用自由文本写整棵树，50 秒后在第 5536 个字符处 JSON 断了 | 要求 JSON 模式（`Output.json()`）；限制思考预算、放大输出上限（Gemini 的思考算在输出里）；JSON 模式失败时从文本里读，读不出就报它的开头 |
| 强模型把旋钮写进了 `of`（`window#axis`），8 个意图全部被 `admit` 拒绝 | 提示词写清 `of` 是实体或成员，不是旋钮 |
| 有一次写出的树没有词汇表、没有信念：这棵树没有任何捷径 | 词汇表和信念写成必填 |
| 写了 `into: "self"`，手势语言不认识，几个手势错就把整棵树拒了 | `self` 也可以是落点；**词汇表的错只丢掉那一条（并报出来），补丁的错才拒绝意图**：错一个词只损失一条捷径，错一个补丁会改坏场景 |
| 弱模型关掉思考：15–30 秒 → **1–2 秒** | `select` 不思考 |
| 弱模型过度自信：把一个情绪"决定"成选项；把"画面拖到另一个画面上"当成"留住"，自称 0.95 | **弱模型的理解是一个判断（belief），不是人的决定**：排在人的决定之下，显示为"模型"，不学进词汇表；**拖动不走弱模型**（只读文字的弱模型读不懂手势） |
| 写了一个关于场景本身的意图（`of: "what I forget"`），它被拒，其余 7 个也跟着被拒 | 编写的树**逐个意图放行**：错的那个留在外面并报出来，其余照常 |
| 有时把"默认"放在选项的最后，而代码的兜底是第一个选项 | `admit` 把补丁等于场景原值的那个选项挪到最前 |
| 强模型被问到那个拖动：准确地回答 none，"没有排序的旋钮，留住的手势是拖出/拖进窗" | — |
| blue 上说「海水是红色」：弱模型没把握，强模型回答 none，"海没有控制颜色的旋钮，需要加一个 `sea.color`"。它是对的：海的蓝色写死在 `paintSea` 里 | **旋钮要老实**：`sea.hue`（离蓝色转了多少度，约 150 是红海）和 `contours.kept` 声明成旋钮。之后强模型读到 `hue` 的说明，自己加了「海的颜色：原样 / 红 / 绿」，这句话学进词汇表 |
| 同一句话，另一次弱模型把它读成「太阳更大」（"红色的海是日落，太阳会更大"），自称 0.75 | **读的东西要对得上说的东西**：话里点名了海（kind 的 `names` 里有「海」），弱模型的理解却只动太阳，就不留，交给强模型（`namedIn`）。画出来的太阳和线稿的海也应答「太阳」「海」 |
| 强模型说"需要一个 `sea.color`"，但界面只显示"无事可做" | none 可以带 `needs`（缺的旋钮）；只留舞台上真有的东西、真没有的旋钮。日志里标出来，面板里汇总成「舞台缺的旋钮」：意图树之外，要改 kind 代码的那一层，从此是一张具体的清单 |
| 弱模型没把握的"停留久一点"升级给强模型：决定"按住时停住等你" | 强模型的决定代表人，**学进词汇表**，下次同一句话走 ① |

最后一次：强模型从真实舞台写出 8 个意图（窗的方向、窗里放几张、窗沿是否磨损、松开时、节奏、大小、尘、留住一个画面），每个 8–12 句说法、多数带 2 个手势、各有一个信念，全部通过和缓存树同一套校验，约 19 秒；它自己把"窗沿是否磨损"标成了要问的那一个，和缓存树的判断一样；弱模型四句话都成了判断，各 1–2 秒；拖动直接到强模型。

学到的：

- **校验管结构，路由管意思。** `admit` / `accept` 拦得住键、kind、旋钮、范围；意思上的错靠"谁有资格做什么"：弱模型只能形成判断（可被人一键覆盖），只有强模型能代人决定、能写进词汇表、能加意图。
- **捷径的错要便宜。** 错的说法丢掉一条，错的补丁拒绝意图，错的判断被人一键改掉；没有一种错会悄悄变成"人决定的"。
- **模型写的语言要跟着模型长。** `into: "self"` 是模型自然会写的，语言接受它，比提示词禁止它更稳。

## 还没回答的

- **人确认一个弱模型的判断时，要不要也学进词汇表。** 现在只学强模型的决定；人把"模型"的判断一键切成自己的，等于确认了那句话的意思，也可以学。
- **重新编写时 key 被重命名。** 决定、学到的词汇按 key 保留；强模型把 `dust|dust` 改叫别的，就丢了（sem 的 `renamedFrom` 可以借过来）。
- **lazy effect 落到场景上。** B5、B6、C4 都需要"模型写的世界按 `under` 缓存"，reintent 的 `effect()` 已经有了，场景这边还没有一个能放 sprite 和文字的槽。
- **代价。** ① 是亚毫秒到几毫秒；② 是一次模型调用（替身约 0.5 s，预览上的真模型 3–14 s）。多少事件该进 ②，取决于预设覆盖了多少。
